## 从熟悉的场景开始，让 Agent 完成任务

赛事以 OctoSense 为核心，面向设计师、产品人、一人公司、学生和开发者。选手从 [官方应用指南](https://octosense.org/cn/#apps) 的 12 个场景中选择主场景：**邮件、即时消息、日历、天气、新闻、音乐、视频、财经、导航、购物与物流、写作与创作、系统与设备**。

例如，收到变更邮件后更新相关日程；从群聊里整理聚会安排；让订单、物流与售后持续更新同一任务。共同目标是让 Agent 接收事件、理解目标、提出行动、获得必要授权、执行并核验结果。生成画面和摘要只是过程，作品要能说明实际完成了什么。

**即时消息以 robrix2 为宿主，主要界面沿用 robrix2。** 任务应关联原会话，用户能检查对象和操作范围，结果能返回来源消息。hagency 软件工厂小程序是这一场景下的协作例子：查看 Agent 分工和任务进展，处理阻塞，核对证据并确认交付；其他场景不要求接入软件工厂。

八个项目构成课程的理解框架，不代表已经全部接通，也不要求每件作品接入全部项目。即时消息以 robrix2 为宿主并沿用其主要 UI；小程序运行、权限和版本机制接入仍在准备，实操范围以公布环境为准。hagency 是软件协作选题的案例，其他场景不要求接入。参考画面、练习数据和真实服务接入必须清楚区分。

## 八个项目，帮助选手理解一件作品如何完成

课程以项目介绍、机制演示和使用方法为主，不把比赛准备变成源码与语法训练。选手需要学会描述目标、组织 Agent、观察结果和作出判断；实现工作可以交给 Agent 协助。

| 项目 | 要理解的机制 | 选手如何借助它完成比赛 |
|---|---|---|
| OctoSense | 面向用户的 Agentic 应用入口，连接状态、操作和结果 | 从邮件、日历、天气等场景确定任务，检查应用是否真正完成事情 |
| Makepad | 原生应用界面的呈现与交互基础 | 向 Agent 说明信息、操作与反馈，观察运行界面并提出改进 |
| octoscode | 终端中的编码协作客户端 | 给 Agent 任务和上下文，查看生成、运行与修改结果，持续反馈 |
| Octoscript | 动态表达应用界面与行为 | 让 Agent 把需求变成可运行应用，并依据使用反馈调整 |
| octos | Agent 运行内核，组织上下文、工具和任务执行 | 理解 Agent 如何获得信息、采取行动、报告进展与结果 |
| OctoLoop | octoscode 中的产品化双环 skill：内环执行，外环计划、观察和独立审查 | 把“执行任务”和“判断完成”分开；人确定目标、批准范围并最终验收 |
| robrix2 | 即时消息宿主，沿用会话、消息和联系人界面 | 从对话里的约定形成任务，检查授权和反馈，让结果回到来源会话 |
| hagency | 软件工厂中的任务组织与多 Agent 协作 | 分配任务、查看阻塞、核对证据并确认交付；作为即时消息下的软件协作示例 |

OctoLoop 是 octoscode 内的双环协作入口。内环负责执行和改进，外环负责计划、观察与独立审查，人在目标、审批和最终验收上保持决定权。课程通过一次任务、一次检查和一次反馈展示这种分工。

## 评奖先看 Agentic，再看技术突破

**最佳 Agentic 奖**评价谁的应用最适合 Agent 自动化：任务是否完成、多步骤操作是否可靠、后续变化是否得到处理、用户能否检查和控制结果。需要展示真实操作与证据，也要说明失败和人工介入。

**最佳技术突破奖**在可运行 Agentic 应用的基础上，进一步评价生态反哺和 OctoSense ROM / 系统突破如何改善任务。达到基础要求的作品都可进入进阶评审，不必先获得最佳 Agentic 奖；技术贡献要有前后对照与复现证据。课程讲清价值和判断方法，选手可以借助 Agent 推进实现，不要求每队额外认领悬赏或 issue。

已公开获奖奖池保持 **¥50,000**，含现金奖金与 MiniMax Token 额度：一等奖 1 名 ¥20,000、二等奖 2 名各 ¥9,000、三等奖 3 名各 ¥4,000，均以团队（含单人队伍）为单位。两类新奖项与这 6 个金额名额的对应关系、能否兼得，以及现场邀请的综合排名办法待正式规则确定；不预设额外奖金或将其改成无奖金荣誉。另提供 MiniMax API 额度和 Kimi 编程权益用于开发，领取方式和使用期限随发放说明公布。

两类奖在同一次复赛中评审，10 月 12 日的线上决赛是答辩与评奖环节，不增加第三轮晋级。现场展示及到场情况不改变线上结果。10 月 18–31 日继续跟进贡献采纳和作品归档。
