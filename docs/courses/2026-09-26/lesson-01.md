## 讲稿与操作提示

### 10:00｜先明确什么叫完成

开场讲述：“今天我们用同一个小任务看四个项目如何合作。用户关心深圳天气是否可靠、能否看懂、取不到数据时怎么办。我们需要让 Agent 知道这些条件，再让应用把执行结果交给人检查。”

展示两种需求：“做个天气 App”和主案例完整意图。让学员指出第二种多了哪些信息：城市、时间、操作、失败处理。提醒：课堂主流程展示当前天气与已有预报；‘明天’必须对应正确预报日期，不能拿当前温度替代。

提问：“截图上有 26°C，能证明任务完成吗？”预期回答包括来源、城市、数据时间、单位、是否真实获取、是否完成用户要求。用这些回答引出验收。

### 10:10｜给每个项目一个清楚的位置

展示 [总览中的关系图](README.md#六个角色两种协作)，先只保留运行部分：用户 → OctoSense 内 AppCard → Octos → 卡片表达与数据 → Makepad 界面。

讲述：“OctoSense 提供应用环境；AppCard 理解请求应该交给哪类应用 Agent，并管理卡片；Octos 负责 Agent 执行；Makepad 负责原生呈现和交互。Octoscript 的卡片表达让结构、数据和操作有明确约束，下午再深入。”

不用 Rust 类型名和协议字段解释分工。学员应能回答：任务理解错了、数据获取失败、按钮无法操作，分别应从哪一段寻找证据。这里是在划分责任，不保证每个故障只有一个原因。

### 10:25｜演示一：从输入意图到操作结果

按 [演示 A](demo-runbook.md#演示-a意图生成与数据结果) 执行：先展示输入，再观察路由和生成，最后实际切换单位或城市。每一步把屏幕停住，让学员说出发生了什么。请求提交后出现“处理中”时，明确任务还没有完成。

重点讲述：“Agent 可以决定如何组织信息；实时天气来自服务。模型写一个可信的数字，和服务返回一个有来源的数字，是两种完全不同的证据。”数据延迟时观察等待提示，失败时如实显示不可用。不要临场要求 Agent 编造空气质量来补空白。

用一张记录表留下：原始意图、显示城市、数据来源、采集时间、实际点击、点击后的变化。生成一次成功只说明这次成功；复用性和可靠性需要更多任务验证。

### 10:45｜Makepad 的价值落实到交互

展示界面在正常、等待和失败三种状态下应如何表达。让学员观察按钮是否能点击、改变单位后数值与标签是否一致、小窗口是否遮挡关键操作。只讲使用效果，不讲布局 DSL 或 GPU 实现。

追问：“如果按钮变了颜色，数值没变，这算成功吗？”将问题落到任务状态，而非视觉反馈。区分卡片源文件、宿主运行后的控件、屏幕截图：三者分别证明表达、运行和某一时刻的外观。

### 11:10｜AppCard 不止一条流程

用两条短流程展示项目的能力：

1. **意图生成卡片：** 任务 → 路由与应用 Agent → 卡片 → 检查 → 数据与宿主 → 用户操作。本课主要练习这条。
2. **服务卡片制作：** 多状态设计 → 经审查的语义映射 → 原生控件与服务规则 → 点击验证 → 证据与交付。选取空调或邮件的现有材料讲机制，不现场跑完整生成与编译流程。

讲述：“设计稿能表达体验意图，但不会自动提供服务规则。取消操作、重复提交、数据过期等行为需要明确设计并验证。”当前源码对新原生检查推荐 Makepad 内置 instrument；部分旧流程仍提到 Studio。课堂不把两套工具说成可以无条件互换。

### 11:25｜练习：把一个场景收敛成一个任务

5 分钟填写用户、输入与结果；5 分钟写一个操作和失败状态；5 分钟与同伴互相验收；5 分钟修改。可沿用天气，也可选邮件摘要、日程整理或即时消息中的待办。

学员必须写出数据来自哪里、用户批准什么、服务不可用时怎么办。即时消息选题绑定 Rinx；此处是任务设计，不宣称其已经接通 AppCard 或所有账号能力。选题扩展留到课后完成。

助教检查一句话：“另一名同学照着这份说明，能判断它完成没有吗？”无法判断的描述，例如“足够智能”“界面高级”，要求换成可观察行为。

### 11:45｜演示二：已有整合路径及其边界

回到真实 OctoSense 宿主中的 AppCard，说明源码已经把完整 AppShell 嵌入宿主。桌面可配置 AppCard 启动本地 Octos；应用层负责其生命周期。课堂不另造一个重复内核。

展示任务从发出到结果出现的两个时刻：“请求已提交”是中间状态；卡片渲染、数据获取和用户操作还需要观察。桌面与 Android 的启动方式不同，通知、分享、WebView 等能力不能从独立 AppCard 直接外推到宿主版本。

如果课前宿主演示未通过，只展示带版本说明的证据或机制图，明确标注为源码路径讲解；保留学员任务设计练习。不要声称最新整合已实机验收。

### 11:55｜交接

请每组用 30 秒说清“用户要什么、谁执行、怎样判断完成”。把任务说明与当前阻塞交给下午的编码 Agent。结束时保留一个具体改动，例如改善失败提示或信息优先级，避免下午重做整套应用。
