## 两条赛道的核心练习

### A：出门前的决策卡与宿主使用

输入城市和活动偏好，展示有来源的天气；改变偏好后更新建议。最小版本使用现有能力。空气质量作为信息设计进阶：数值、指标标准、时间、图例与 Unknown / 失败状态必须齐全，不能把色块变化当作任务完成。

OctoSense 练习让另一位同学查找、打开、操作、切换和返回已打包应用。AppCard 与 OctoSense 当前代码不是默认接通的一条产品链；跨仓库协议集成另算成果。非 Rust 团队使用已验证的预编译 Reference / 环境包。

Converter 是 L1 计算与事件样例，不能作为纯 L0 无算术示例。本轮其预设点击未通过；开课前修复复验，否则只用于诊断练习。

### B：软件工厂任务状态小程序

首个示例限定一个已授权的 agent scope：展示任务标题、执行/等待状态、更新时间；用户筛选、刷新或打开对应讨论，核对数据与结果。先使用可重放 fixture，再在已发布的本地 robrix2 + hagency 环境内复验。避免第一课就要求全局 DAG、跨 Agent 汇总或工厂写操作。

进阶方向包括任务与阻塞看板、Agent 工作状态、结果验收工作台、团队交接。超出当前受限 snapshot 的任务依赖、CI 证据和跨 Agent 数据应作为能力层扩展。会影响工厂运行的操作由原生宿主确认，再由服务验证；小程序不接收 dashboard token，也不代替现有审批。

教学重点是完整任务：找到需要处理的事项 → 理解状态来源 → 操作 → 核对结果 → 处理拒绝或过期。已有小程序示例只用于解释 runtime、权限、版本机制，不要求选手复制其 UI 或选题。

## Pipeline 专题：区分两种生成路径

| 路径 | 教学链路 | 必须留下的证据 |
|---|---|---|
| AppCard | 意图/规则 → 生成 → L0/L1 校验 → 渲染 → 事件与结果 | 输入、validator、几何/交互结果；seed 与模型生成分别标明 |
| Robrix Agent2App | create/refine → ACP → Splash 校验 → 有界修复 → 安装版本 → 宿主实例 | 首次输出与修复轮次、取消/失败、权限、diff/rollback；fake ACP 不等于真实模型已接通 |

style-factory / 视觉评审选题需要固定输入、冻结对照、盲评交换顺序、保留首轮与重试，记录预算；不能只拿最高分或最好看的截图当总体结果。hagency 负责工厂任务编排，与生成小程序所用的 ACP provider 分开讲授。

## 发布课程前的准备条件

1. **锁版本环境包**：实际支持的 OS、binary hash、仓库/子模块 revision、Studio/harness 兼容版本、能力清单。B 赛道以 robrix2 原生 UI 与已发布的 same-host 接入为准，不要求手机。
2. **B 赛道接入状态**：实施计划在 `robrix2/docs/superpowers/plans/2026-09-12-agent2app-hagency-miniapps.md`（位于独立 robrix2 仓库）。hagency 与 robrix2 当前客户端契约名不同，双方 manifest 仍是 development；正式接口未发布前只可进行明确标注的 fixture 实验。9/18 18:00 前说明初赛实操环境与 fixture 提交接受范围；9/30 公布复赛名单时确认复赛环境。正式环境未就绪时，主办方必须统一公布替代运行环境、fixture 验收边界与等价评分，不得将其称作已完成 robrix2 集成。
3. **受控生成服务**：地址、连接诊断、模型额度、取消/修复边界与离线入口。区分模型不可达、数据服务不可达和脚本被拒绝。
4. **合格示例**：A 至少一张事件通过的卡与一张有来源的数据卡；修复 `vibrant` 文档不一致并说明 NO-ROUTER 默认流程。B 至少一个符合 robrix2 UI 的任务状态应用和一组权限/过期练习。
5. **真实回放 runner**：能拦截数据能力并控制在线刷新，注入正常/空/拒绝/超时/过期。仅存几个 JSON 文件不算完成回放。开课前无法隔离数据源时，先教已验证的本地状态练习。
6. **统一证据模板**：输入、期望、实际、前后截图、日志、版本、来源与已知限制。Studio 地址/build ID 从本次运行查询；不复制老师的历史值，不使用真实团队秘密或审批任务做课堂 fixture。

## 悬赏调整建议

网站新增“hagency 软件工厂小程序”和“小程序能力与契约测试”，保留原有工具链选题。下列细化内容供赛前确定认领入口、导师、难度与分值，尚非已批准奖金表。

| 方向 | 可验收成果 |
|---|---|
| hagency 任务/状态/结果/交接小程序 | 明确场景 + 原生容器中的应用 + 数据接入说明 + 一次任务完成证据 |
| 小程序能力与契约测试 | 一个受限投影或状态回放、权限测试；接回应用，覆盖拒绝/过期/跨 scope |
| L0 Playground / check-ui CLI / LSP | 工程化已有 validator；非法输入非零退出、诊断定位和版本兼容，本轮 `l0validate` 非法卡退出 0 可作具体案例 |
| 诊断、结构化 lint、L1 规范 | 从现有规则与规范缺口切入，正反例同步；能力归属依据实际 AppCard / Octoscript 代码 |
| 空气质量与卡片事件 | 有效数据可读、null/错误不显示为 0；converter 操作必须有状态断言 |
| Studio / transport 与生成 pipeline | 断线恢复可复现，入口无作者路径依赖；validate/render/judge 分离，失败记录完整 |
| UI protocol / schema / skill 脚手架 | 明确协议版本与一条应用演示，贡献可被另一个团队接用 |

## 比赛中的验收节点

9/28 初赛提交需求与可运行最小原型，9/29–30 独立评审并返回反馈；10/1–10/8 复赛完善完整任务，10/9–10 复现与评分。初赛原型展示“真实输入 → 可读结果 → 一次状态变化”及一个失败状态。复赛每队至少认领一项悬赏或合格 issue；可复现缺口 issue 也满足要求，不强制选修技术课程。10/8 复赛交付 `app.md`、应用源码/包、能力说明、版本与复现命令、测试证据、两张截图、已知限制；fixture、参考卡片、fake provider 与真实在线结果逐项标明。

3 分钟演示：30 秒场景；60 秒操作与结果；45 秒数据与失败状态；45 秒证据与限制。随后 2 分钟讲清作品为项目增加了什么。

初赛采用需求价值 30%、核心流程可用性 40%、数据来源与失败状态 20%、复现与材料 10%。复赛与决赛评分保持项目反哺 40%、创意与完成度 30%、现场演示 20%、协作与文档 10%。赛前发布两条赛道的等价采纳清单，spec、可复现应用、fixture、诊断、组件与代码均可计入，技术深度不成为应用层作品的资格门槛。

决赛准备期为 10/11–16：10/12 演示训练，10/14 线上彩排，10/15 18:00 冻结展示包，10/16 设备联调，10/17 现场展示。每队在 5 分钟展示之外预留 2 分钟问答与 1 分钟切换；完整会务时段另行确认。
